Назначение

Бесплатная автономная утилита строит предварительную карту сервисов Linux- или
Windows-сервера
университета. Она помогает понять, какие сайты, прокси-маршруты, службы,
контейнеры и локальные порты обнаружены, а также где нужна ручная проверка перед
возвращением сервиса в сеть. Один публичный IP не означает один физический сервер:
запустите сборщик на каждом доступном узле и объедините результаты.

Утилита работает локально без подключения к интернету и без сторонних библиотек.
Она не выполняет сетевое сканирование, не входит в приложения, не подбирает
пароли, не эксплуатирует уязвимости и не меняет конфигурацию сервера.

Кому запускать

Только сотруднику с полномочиями на обследование конкретного сервера. Для Linux
нужен Python 3.8 или новее; для Windows — PowerShell 2.0 или новее. Установки
дополнительных пакетов на Windows не требуется.
Часть сведений может быть недоступна обычному пользователю; отчёт отметит такие
пробелы. Утилита не вызывает sudo и не повышает права.

Быстрый запуск на Linux

1. Скопируйте файлы проекта в отдельную папку, доступную для записи.
2. В терминале перейдите в эту папку.
3. Проверьте: python3 --version
4. Запустите: sh run.sh
   Альтернатива: python3 campus_mapper.py collect
5. Появится папка campus-report-ГГГГММДД-ЧЧММСС.

Запуск на Windows

Используйте отдельный архив Windows 0.3.0 и инструкцию WINDOWS_README.txt.
В PowerShell запустите .\windows_mapper.ps1 на каждом узле. Отчёт по умолчанию
сохраняется в %LOCALAPPDATA%\FelixFonsCampusMapper. При невозможности ужесточить
права на папку данные всё равно записываются, а summary.txt предупреждает об этом.
Основная целевая версия сервера — Windows Server 2008 R2. Для обычного Server
2008 SP2 нужен отдельно установленный PowerShell 2.0; испытаний на нём пока нет.

Вывод

summary.txt             Сводка для ответственного сотрудника.
service_cards.txt       Карточки сайтов и сервисов с вопросами перед включением.
inventory.private.json  Закрытая техническая карта для объединения серверов.
manifest.sha256         Контрольные суммы этих трёх файлов.

На Linux каталог отчёта создаётся с правами 0700, файлы — 0600. Все четыре
файла предназначены только для внутреннего пользования университета: даже
текстовые отчёты показывают имена сайтов, контейнеров и узлов. Не размещайте
отчёты в публичном репозитории или открытых обсуждениях. JSON дополнительно
содержит внутренние адреса и более полный перечень пакетов. Пароли и ключи
утилита целенаправленно не собирает.

Объединение отчётов с нескольких серверов

Скопируйте inventory.private.json каждого обследованного узла в закрытую папку
под разными именами. Затем выполните:

python3 campus_mapper.py merge edge.json app.json --out campus-combined

Можно указать больше файлов. Объединение допустимо на Linux или Windows с
Python 3.8+. В Windows права выходной папки зависят от выбранного места хранения;
используйте закрытую папку. Файлы разных университетов не объединяйте.

Что проверяется

- ОС, состояние ASLR по системному параметру Linux, место на корневом диске,
  версии локальных команд и установленных пакетов.
- Слушающие TCP-порты, доступные сведения о процессах и файлах служб systemd.
- Работающие и остановленные контейнеры Docker из стандартного локального
  Unix-сокета /var/run/docker.sock, опубликованные порты и health. Удалённый
  Docker из DOCKER_HOST и нестандартная rootless-установка не обследуются.
- Типичные конфигурации nginx и Apache, имена сайтов и направления маршрутов.
- PHP-FPM-пулы, признаки значения session.upload_progress.enabled.
- Срок действия доступных файлов сертификатов, признаки задач резервирования.
- Количество ошибок и заранее определённые категории журналов без текста записей.
- Статические SSH-перенаправления из доступных файлов служб.
- Офлайн-сверка отдельных версий PHP, Node.js, nginx и Apache с правилами, зафиксированными
  25 октября 2026 года, и признаки возможной открытости портов данных.
- Для трёх октябрьских CVE nginx отдельно сопоставляются диапазоны версий и
  безопасные булевы признаки нужных директив. Сами строки конфигурации в отчёт
  не попадают. Совпадение признаков на одном узле ещё не подтверждает, что они
  работают вместе для одного запроса; отсутствие признака не исключает иной
  конфигурации, шаблонов, контейнера или исправленного пакета.

Границы вывода

Версия команды или метка контейнера не доказывает версию работающего сайта,
наличие конкретной уязвимости или взлом. Порт на всех интерфейсах не доказывает
доступность из интернета. Недоступный ресурс не означает, что ошибка исправлена.
Утилита не проверяет вход, права пользователей, восстановление из копии,
содержимое БД, исходный код приложения, зависимости внутри образов,
сетевые правила и внешний TLS-ответ. Она не читает SSI-страницы и не определяет
применимость CVE к конкретному запросу. Состояние ASLR относится к узлу и не
доказывает возможность или невозможность эксплуатации. Она читает ограниченную выборку из типичных
расположений конфигураций; ограничения доступа и лимиты записей могут дать
неполную карту. Она не выдаёт автоматического разрешения на включение сервиса.

Правила бюллетеней не обновляются в изолированной сети. Их даты, пороги и
официальные источники перечислены в BULLETINS.txt. После семи дней с даты
снимка отчёт предупреждает об их возрасте. Перед решением о публикации нужно
сверить свежие бюллетени разработчика и поставщика ОС, реальную версию процесса,
резервную копию, авторизацию и работу сервиса. Для систем с учётными записями
проверка входа и ролей проводится отдельно.
